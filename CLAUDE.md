# obd-v2x-dongle — project rules

## Part sourcing (applies to every part choice)
- **PCBWay assembly first.** Pick parts PCBWay can source and assemble (they buy from Digi-Key / Mouser / LCSC etc.). Prefer common, in-stock, multi-source parts.
- A few parts that PCBWay can't source are acceptable (consigned or hand-soldered), but call them out in `docs/bom-notes.md`.
- Every part in the schematic needs a real footprint and a real MPN in the Value (or an `MPN` field) before ordering.

## Design constraints
- ITS-G5 is **receive-only** (ESP32-C5 in undocumented 802.11p mode via esphome-its-g5). Don't add V2X transmit features.
- LTE modem is the Quectel **EC200U-EU** (Cat 1, chosen over EG25-G for cost: ~$13 vs ~$66). Its logic I/O is **1.8 V**; ESP32-C5 is 3.3 V. Everything between them goes through the TXS0108E (U402) or the open-collector NPN drivers (PWRKEY, RESET_N).
- The dongle must **not** terminate the vehicle CAN bus (no 120 Ω).
- ESP32-C5 strapping: GPIO28 = BOOT (low = download), GPIO27 must be high at boot (LED data line is fine), GPIO26/25/7 floating OK.

## KiCad
- KiCad 10, project in `hardware/`. Scripts find KiCad via `hardware/tools/kicad_env.py` (`KICAD_DIR` env var,
  `kicad-cli` on PATH, or the default install locations). Never commit absolute local paths, usernames or
  machine names (generated files included); keep personal info out of the repo.
- Git: commit as the repo's configured user (GitHub no-reply address). **No `Co-Authored-By` / "Generated with"
  trailers or other AI attribution** in commit messages or PR descriptions.
- Sheets power / vehicle / mcu / lte are **generated**: edit `hardware/tools/gen_schematic.py`, then
  `python hardware/tools/gen_schematic.py`. Don't hand-edit those `.kicad_sch` files (changes get overwritten).
  Layout rules: real wires inside a block, GND/rail power symbols, global labels only for cross-sheet nets.
- After any change run `python hardware/tools/check_netlist.py` — connectivity must match
  `hardware/tools/reference.net`. When a connectivity change is intended, review it and then refresh
  it with `python hardware/tools/check_netlist.py --update` (strips the absolute source path).
- Project symbols (incl. rail power symbols) are generated: edit `hardware/lib/gen_symbols.py`, run it.
  The EC200U footprint is generated by `hardware/lib/gen_footprints.py`; the ESP32-C5 footprint is vendored from
  Espressif (see `hardware/lib/README.md`). Run `python hardware/tools/check_footprints.py` after symbol or footprint changes.
- ERC: `kicad-cli sch erc hardware/obd-v2x-dongle.kicad_sch` (expect 0 errors, 0 warnings).
  PDF: `kicad-cli sch export pdf -o docs/schematic.pdf hardware/obd-v2x-dongle.kicad_sch`.
- EC200U: PWRKEY must be held low >= 2 s to power on; pin 35 is a BT/Wi-Fi-scan antenna (unused), there is no LTE diversity antenna.

## PCB
- 52 x 74 mm, 4 layers: In1 = solid GND plane (no tracks), In2 = routing + GND pour; parts on both sides;
  OBD plug at the front edge, housing overhangs 12 mm.
- The board was bootstrapped by `hardware/tools/gen_pcb.py` (run with KiCad's bundled Python, `<KiCad>/bin/python`).
  `preroute.py` (RF lines, buck SW node) and `silk.py` (reference placement) also run with it.
  It refuses to overwrite an existing board; `--force` regenerates and **loses all routing/manual moves**.
  From routing on, edit `obd-v2x-dongle.kicad_pcb` in KiCad; schematic changes via Tools > Update PCB from Schematic.
- Check: `kicad-cli pcb drc --schematic-parity --refill-zones hardware/obd-v2x-dongle.kicad_pcb` (parity must be 0).
- Routed with Freerouting (export DSN with In1 set to `(type power)` so it stays a solid plane, outer GND pours
  removed from the export) plus `hardware/tools/maze.py` for single connections and GND stitching vias.
  The buck switch node is locked 1 mm F.Cu tracks; keep other nets out of it.
- Current state: DRC 0 errors, 0 unconnected, parity 0 (only cosmetic silk warnings).
- RF net class width (0.35 mm) is a 50 ohm placeholder: confirm with PCBWay's stack-up before ordering.
