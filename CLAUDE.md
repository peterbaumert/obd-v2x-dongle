# obd-v2x-dongle — project rules

## Repo layout
- `rev1/` is the first board (ordered 2026-11-20, order cancelled 2026-11-24 in favour of rev 2): `rev1/hardware/`, `rev1/mechanical/`, `rev1/docs/`. The
  KiCad, PCB and Case sections below describe rev 1.
- `rev2/` is the next revision (two stacked boards, 25 mm case). Start from `rev2/README.md`. Its two KiCad projects
  (`rev2/hardware/carrier`, `rev2/hardware/upper`) are generated by `rev2/hardware/tools/gen_schematic.py`; after any
  change run `check_stack.py` and `check_vs_rev1.py` (both in `rev2/hardware/tools`) and ERC on both (expect 0 / 0).
  Boards: `<KiCad>/bin/python rev2/hardware/tools/gen_pcb.py carrier|upper` (first-pass placement, unrouted;
  `--force` loses routing). Keep `rev2/mechanical/stack.py` in step with the big parts' positions.
  Order files: `<KiCad>/bin/python rev2/hardware/tools/fab.py`; notes and stock in `rev2/docs/bom-notes.md`.
  Both rev 2 boards are 4 layers (In1 GND plane) and fully routed after the 2026-11-21 layout review (0 unconnected,
  no rule errors, parity 0), with hand edits: the `.kicad_pcb` files are the source, do not run `gen_pcb.py --force`.
  Last connections and local fixes: by hand (KiCad MCP or pcbnew), checking the other side's pads first (the modem
  sits under the carrier's top parts). Tools: `rev2/README.md` ("Routing"); Freerouting jar from `FREEROUTING_JAR`.
  F.Cu under the GNSS patch stays ground (rule area in its footprint).
- `firmware/` is shared by both revisions.

## Part sourcing (applies to every part choice)
- **PCBWay assembly first.** Pick parts PCBWay can source and assemble (they buy from Digi-Key / Mouser / LCSC etc.). Prefer common, in-stock, multi-source parts.
- A few parts that PCBWay can't source are acceptable (consigned or hand-soldered), but call them out in `rev1/docs/bom-notes.md`.
- Every part in the schematic needs a real footprint and a real MPN in the Value (or an `MPN` field) before ordering.

## Design constraints
- ITS-G5 is **receive-only** (ESP32-C5 in undocumented 802.11p mode via esphome-its-g5). Don't add V2X transmit features.
- LTE modem is the Quectel **EC200U-EU** (Cat 1, chosen over EG25-G for cost: ~$13 vs ~$66). Its logic I/O is **1.8 V**; ESP32-C5 is 3.3 V. Everything between them goes through the TXS0108E (U402) or the open-collector NPN drivers (PWRKEY, RESET_N).
- The dongle must **not** terminate the vehicle CAN bus (no 120 Ω).
- ESP32-C5 strapping: GPIO28 = BOOT (low = download), GPIO27 must be high at boot (LED data line is fine), GPIO26/25/7 floating OK.

## KiCad
- KiCad 10, project in `rev1/hardware/`. Scripts find KiCad via `rev1/hardware/tools/kicad_env.py` (`KICAD_DIR` env var,
  `kicad-cli` on PATH, or the default install locations). Never commit absolute local paths, usernames or
  machine names (generated files included); keep personal info out of the repo.
- Git: commit as the repo's configured user (GitHub no-reply address). **No `Co-Authored-By` / "Generated with"
  trailers or other AI attribution** in commit messages or PR descriptions.
- Sheets power / vehicle / mcu / lte are **generated**: edit `rev1/hardware/tools/gen_schematic.py`, then
  `python rev1/hardware/tools/gen_schematic.py`. Don't hand-edit those `.kicad_sch` files (changes get overwritten).
  Layout rules: real wires inside a block, GND/rail power symbols, global labels only for cross-sheet nets.
- After any change run `python rev1/hardware/tools/check_netlist.py` — connectivity must match
  `rev1/hardware/tools/reference.net`. When a connectivity change is intended, review it and then refresh
  it with `python rev1/hardware/tools/check_netlist.py --update` (strips the absolute source path).
- Project symbols (incl. rail power symbols) are generated: edit `rev1/hardware/lib/gen_symbols.py`, run it.
  The EC200U footprint is generated by `rev1/hardware/lib/gen_footprints.py`; the ESP32-C5 footprint is vendored from
  Espressif (see `rev1/hardware/lib/README.md`). Run `python rev1/hardware/tools/check_footprints.py` after symbol or footprint changes.
- ERC: `kicad-cli sch erc rev1/hardware/obd-v2x-dongle.kicad_sch` (expect 0 errors, 0 warnings).
  PDF: `kicad-cli sch export pdf -o rev1/docs/schematic.pdf rev1/hardware/obd-v2x-dongle.kicad_sch`.
- EC200U: PWRKEY must be held low >= 2 s to power on; pin 35 is a BT/Wi-Fi-scan antenna (unused), there is no LTE diversity antenna.
- J403 (GNSS U.FL) carries 3.3 V active-antenna bias (U405 latch-off switch, on while the modem is powered); C417 is the
  DC block to the modem. All ESP32 GPIOs are in use.

## PCB
- 52 x 64.4 mm, 4 layers: In1 = solid GND plane (no tracks), In2 = routing + GND pour; parts on both sides;
  OBD plug at the front edge: the whole housing (20 mm) sits in front of the board (front edge 0.35 mm behind
  the housing rear face) so the case can grip its retention groove on all four sides. CR-PG001 drawing: the
  "5.65" goes to the outer leg EDGE (leg centres 5.25 / 2.25 behind the rear face), and the leg tips end level
  with the housing bottom, so the housing sits ~1 mm below the board's bottom face.
- The board was bootstrapped by `rev1/hardware/tools/gen_pcb.py` (run with KiCad's bundled Python, `<KiCad>/bin/python`).
  `preroute.py` (RF lines, buck SW node) and `silk.py` (reference placement) also run with it.
  It refuses to overwrite an existing board; `--force` regenerates and **loses all routing/manual moves**.
  From routing on, edit `obd-v2x-dongle.kicad_pcb` in KiCad; schematic changes via Tools > Update PCB from Schematic.
- Check: `kicad-cli pcb drc --schematic-parity --refill-zones rev1/hardware/obd-v2x-dongle.kicad_pcb` (parity must be 0).
- Routed with Freerouting (export DSN with In1 set to `(type power)` **and** a `(plane GND (polygon In1.Cu ...))`
  entry, otherwise Freerouting treats In1 as a signal layer and routes on it; outer GND pours removed from the export)
  plus `rev1/hardware/tools/maze.py` for single connections and GND stitching vias. Use the Freerouting jar (Java 25);
  the native freerouting-cli build crashes on serialization. Load/save the board from `rev1/hardware/` with pcbnew,
  saving a board loaded from elsewhere rewrites `obd-v2x-dongle.kicad_pro` with default rules.
  The buck switch node is locked 1 mm F.Cu tracks; keep other nets out of it.
- Schematic changes reach the routed board via `rev1/hardware/tools/sync_pcb.py` (adds new parts, updates nets/fields,
  rips copper of split nets and under new parts); then `route_unconnected.py` / Freerouting (lock pre-routes and
  **save** the lock first, Freerouting leaves locked copper out of its result).
- Current state: fully routed. DRC 0 errors / 0 unconnected, parity 0, ERC 0/0 (only cosmetic silk warnings).
  Only the pre-routes (RF lines + their GND vias, buck SW node) are locked.
- RF net class: 0.32 mm GCPW, 0.25 mm gap = ~50 ohm on PCBWay's standard 1.6 mm 4-layer stack-up (order with 50 ohm
  impedance control on L1). No vias in SMD pads (maze.py enforces it; only the ESP32 EPAD thermal vias).
- Fab outputs: `<KiCad>/bin/python rev1/hardware/tools/fab.py` -> `rev1/hardware/fab/` (Gerber zip, BOM, CPL; git-ignored), also
  refreshes `rev1/docs/bom.csv`. Order settings in `rev1/docs/design-review.md`.

## Case
- `rev1/mechanical/case.py` (build123d, system Python: `pip install build123d pyvista`) generates the two-part case
  (`rev1/mechanical/out/*.stl|step|png`). `python rev1/mechanical/case.py --check --render` exports the board STEP via kicad-cli,
  checks the case against PCB, parts and OBD plug (must say "check passed"). Re-run after board changes.
- Plug dimensions marked MEASURE are from the drawing / estimated: update from the real Elecbee plug.
